FIVE RUNS OF benchmark.py, NO MANUAL RESET AT ANY POINT
======================================================

Runs 1 to 3 are three CONSECUTIVE runs of the suite, which is the re-runnability check.
Run 1 rebuilt the fixture (no provenance record existed yet). Runs 2 and 3 reused it
after the provenance check confirmed it still matched the warehouse.

Run 4 came straight after a second full ./run.sh, which rebuilds the whole warehouse and
so evicts the 166 MB lab from a 128 MB shared_buffers. Its provenance check found the
rebuilt warehouse byte identical to the old one and reused the fixture. It is the run a
reviewer following the README will get, and it is slower in both columns.

Run 5 followed a deliberately invalidated provenance record, to exercise the branch a
genuinely changed warehouse would take. It dropped the fixture and rebuilt it cleanly.

Every run exited 0. PERFORMANCE.md quotes the range across all five and the MINIMUM
speedup of the five as the figure to carry into a conversation.
